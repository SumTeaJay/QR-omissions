# План выполнения тестового задания

## Цель

Создать работающий прототип модуля стартапов и вакансий для будущего Telegram Mini App: backend на Python, PostgreSQL, адаптивный frontend и запуск через Docker Compose.

## Основной пользовательский сценарий

1. Пользователь входит под тестовым аккаунтом.
2. Создаёт публикацию типа «стартап» или «вакансия».
3. Другой пользователь видит публикацию в ленте и отправляет отклик.
4. Автор публикации принимает или отклоняет отклик.
5. Откликнувшийся видит результат решения в личном кабинете.

## Технологические решения

- Backend: FastAPI, SQLAlchemy 2, Alembic, Pydantic.
- Database: PostgreSQL.
- Frontend: React, TypeScript, Vite.
- Infrastructure: Docker Compose.
- Authentication: JWT-based demo sessions with access control.
- Testing: pytest for API and scenario tests; frontend checks with the project build.

## Этапы

1. Подготовить Git-репозиторий, структуру проекта, Docker Compose, переменные окружения и README.
2. Реализовать модели User, Profile, Post и Response, миграции, seed-данные и API авторизации.
3. Реализовать API ленты, публикаций, откликов и личного кабинета с проверками прав.
4. Создать адаптивный React-интерфейс: вход, лента, карточка, создание публикации и кабинет.
5. Добавить тесты ключевого сценария, повторных действий, ошибок и разграничения доступа.
6. Провести интеграционную проверку через Docker Compose, дополнить README и подготовить GitHub-репозиторий.

## Критерии готовности

- Два тестовых аккаунта проходят полный сценарий публикации и отклика.
- Данные сохраняются в PostgreSQL.
- Нельзя повторно отправить отклик или откликнуться на свою публикацию.
- Только автор публикации меняет статус отклика.
- Реализованы загрузка, ошибки и пустые состояния интерфейса.
- Проект запускается через Docker Compose одной последовательностью команд.
- README содержит запуск, аккаунты, решения, AI-практики и фактически потраченное время.

## Допущения

- Telegram WebApp SDK пока не подключается; UI остаётся совместимым с последующей интеграцией.
- Реальные Telegram ID, внешние интеграции, файлы, уведомления, Redis и Kafka не входят в обязательный объём.
- Интернет-развёртывание является бонусом после стабильного локального запуска.
