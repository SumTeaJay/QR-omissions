# План реализации тестового задания: QR-пропуск и начисление баллов

## Краткое резюме

Реализовать в репозитории [QR-omissions](https://github.com/SumTeaJay/QR-omissions) сервис на Python 3.10+ с FastAPI, SQLAlchemy, PostgreSQL и aiogram 3.

Сдача ориентирована на локальный запуск одной командой через Docker Compose. Внешний deployment не включается.

## Основные изменения

- Создать слоистую структуру проекта:
  - Telegram-бот;
  - FastAPI API;
  - сервисы бизнес-логики;
  - репозитории и SQLAlchemy-модели;
  - Alembic-миграции;
  - конфигурация через `.env`.

- Реализовать модели PostgreSQL:
  - `guests`: имя, категория, `telegram_id`, UUID и nonce токена;
  - `check_ins`: гость, Telegram ID организатора, время, уникальность check-in для гостя;
  - `point_transactions`: гость, организатор, сумма, причина, тип начисления, время;
  - одноразовость обеспечить уникальным ограничением в БД и транзакцией.

- Реализовать подписанный QR-токен:
  - payload с версией, UUID гостя и nonce;
  - HMAC-SHA256 через секрет из окружения;
  - проверка подписи через constant-time comparison;
  - подмена идентификатора, повреждение токена и неверный секрет должны отклоняться.

- Реализовать Telegram-сценарии:
  - `/qr` выдаёт гостю PNG с QR-кодом;
  - организатор определяется по `ORGANIZER_TELEGRAM_IDS`;
  - фото QR распознаётся через `opencv-python-headless`;
  - ручной ввод токена остаётся fallback;
  - после успешного распознавания показывается карточка гостя: имя, категория, текущие баллы и статус check-in;
  - кнопка check-in один раз начисляет значение из `CHECKIN_POINTS`;
  - отдельная кнопка добавляет ручной бонус с суммой и причиной;
  - диапазон бонуса задаётся `BONUS_MIN_POINTS` и `BONUS_MAX_POINTS`;
  - повторный check-in не создаёт новую запись и не начисляет баллы.

- Добавить администрирование гостей:
  - защищённый `POST /admin/guests` с `X-Admin-Key`;
  - команда seed для демонстрационных данных;
  - гостевая саморегистрация не используется.

- Добавить API:
  - `GET /health`;
  - административное создание гостя;
  - получение карточки по проверенному токену для внутреннего и тестового использования.

- Подготовить Docker Compose:
  - контейнер приложения;
  - контейнер PostgreSQL;
  - healthcheck базы;
  - автоматический запуск миграций;
  - запуск командой `docker compose up --build`.

- Подготовить `.env.example` без реальных секретов.

- Написать README:
  - запуск и переменные окружения;
  - архитектура и схема данных;
  - сценарии гостя и организатора;
  - правила одноразового check-in;
  - описание QR-распознавания и fallback;
  - команды тестирования;
  - описание использования Codex/ИИ, ручных проверок и сознательных исправлений;
  - инструкция публикации в указанный GitHub-репозиторий.

## Проверка

Добавить pytest-тесты для:

- выпуска и проверки корректного токена;
- отказа при изменённом payload или подписи;
- отказа при неверном секрете;
- одноразового check-in при повторном запросе;
- корректного суммирования журнала начислений;
- валидации диапазона ручного бонуса;
- проверки списка доверенных организаторов;
- round-trip генерации и распознавания QR.

После реализации выполнить Docker smoke-check: поднять Compose, применить миграции, проверить `/health`, создать demo-гостя, получить QR и проверить сценарии check-in/повторного сканирования.

## Правило фиксации изменений

После каждого логического шага:

1. Выполнить относящиеся к шагу проверки и тесты.
2. Проверить отсутствие секретов и случайных файлов.
3. Создать отдельный атомарный коммит с понятным сообщением.
4. Сразу отправить коммит (`push`) в `https://github.com/SumTeaJay/QR-omissions`.
5. Не переходить к следующему шагу при незакоммиченных изменениях или неотправленном коммите.

## Зафиксированные предположения

- Используется один текущий event; отдельная multi-event модель не требуется.
- Бот работает в polling-режиме.
- Все значения баллов и секреты задаются через окружение.
- Гости создаются администратором или seed-командой.
- OpenCV выбран вместо pyzbar, чтобы избежать системной зависимости ZBar.
- Локальная папка будет инициализирована как Git-репозиторий, подключена к указанному GitHub-репозиторию и опубликована после прохождения проверок.
